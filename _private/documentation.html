Link Cleaner quickstart

  1. Sign in to the developer portal and open API tokens.
  2. Create a token and copy it. The portal displays the full token only when you create it.
  3. Run the example in Bash and paste the token at the prompt.
read -rs -p 'API token: ' DISC_TOOLS_API_KEY; printf '\n'
curl -sS -i https://developers.disc-tools.de/api/v1/link-cleaner \
  -A 'DiscToolsExample/1.0' \
  -H "Authorization: Bearer $DISC_TOOLS_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com/watch?v=42&utm_source=discord"}'
unset DISC_TOOLS_API_KEY

Expect HTTP 200 and a JSON response whose url is https://example.com/watch?v=42. If you write your own client, set a descriptive User-Agent such as MyDiscordBot/1.0.

POST /api/v1/link-cleaner

Send a JSON object with one absolute HTTP or HTTPS url of up to 4,096 characters. The API processes the URL as text and never fetches the destination.

Every successful response includes the final URL as a string in url. If cleaning would risk invalidating a signature, that string is the original URL. Invalid input returns HTTP 400 with an error. stats.total matches the number of distinct names in removed, and stats.categories adds up to that same total. stats.occurrences counts every removal, including repeated keys. candidates lists possible trackers that were kept, and candidate_details gives each candidate a name and category. The response also includes request_id.

Tracking rules

  • Campaigns and ads — utm_* and platform-specific parameters such as gclid, gad_source, fbclid, ttclid, msclkid, twclid, and li_fat_id.
  • Email, affiliate and analytics — identifiers such as mc_cid, _hsmi, mkt_tok, irclickid, and mtm_campaign.
  • Site-specific sharing — parameters such as YouTube si, TikTok sender_device, and Amazon product-link tag are scoped to their platforms.

The cleaner preserves fragments, recognized signed URLs and ambiguous identifiers such as session_id. Known redirect fields can contain HTTP or HTTPS destinations. The cleaner handles up to four layers of percent encoding and visits up to three nested destinations by default. Removal statistics include all visited levels. Set "recursive": false in the single or batch request body to clean only the outer URLs.

  • 400 — Check that the JSON contains an absolute HTTP or HTTPS URL.
  • 401 — Check the Bearer token and confirm your account still has API access. Create a new token if the old one was revoked.
  • 429 — Slow down requests. Wait for Retry-After when present. Otherwise, wait and increase the delay between retries.
  • 503 — The service is temporarily unavailable. Try again after a short delay.

Signed URLs

When the cleaner detects a signature marker, it preserves that URL and any redirect data it contains byte for byte. protected_urls lists the nesting depth and detected signature parameter names. retained lists recognized trackers left in place with their category, depth, and reason. signed_url means the tracker is in a signed URL. signed_ancestor means editing the nested URL could change a signed parent. These trackers do not count as removals.

POST /api/v1/link-cleaner/batch

Send between 1 and 20 URLs in a urls array. The JSON request body is limited to 10 KB.

{"urls":["https://example.com/?utm_source=discord","https://example.org/"]}

A successful batch returns a results array in input order. Each item has a status and either url and removed, or an error.

POST /api/v1/discord/timestamp

Send a UTC date and time in ISO format or provide timestamp as Unix seconds. Choose a style from t, T, d, D, f, F, or R. The default is f.

{"datetime":"2026-12-01T18:00:00Z","style":"R"}

The response contains timestamp, style, markup for Discord, and request_id. Both POST endpoints use the same Bearer token header as Link Cleaner.

GET /api/v1/status

This public endpoint returns login and premium booleans for OAuth configuration and database query availability. See API Status for the browser checks.
